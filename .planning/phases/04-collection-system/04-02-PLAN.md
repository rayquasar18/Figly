    - getItemDetail(itemId, viewerId?): returns item with ownerCount, series info, category info, viewer status

    - toggleOwned(userId, itemId): add to owned if not owned (remove from wishlist first), remove if already owned. Returns { success: true, isOwned: boolean }
    - toggleWishlist(userId, itemId): add to wishlist if not wishlisted (remove from owned first), remove if already wishlisted. Returns { success: true, isWishlisted: boolean }
    - followCategory(userId, categoryId): toggle follow. Returns { success: true, isFollowed: boolean }
    - followSeries(userId, seriesId): toggle follow. Returns { success: true, isFollowed: boolean }

  <action>
    **CollectionService (backend/src/collection/collection.service.ts):**
    Create service with PrismaService injection. Methods:

    1. `getCategories()`: findMany with include `_count: { select: { series: true } }` and nested series._count.items aggregated. Order by position asc.

    2. `getSeriesByCategory(categorySlug, viewerId?)`: Find category by slug, then findMany series with `_count: { select: { items: true } }`. If viewerId, batch check SeriesFollow with IN clause.

    3. `getItemsBySeries(categorySlug, seriesSlug, viewerId?, cursor?, take=20)`: Find series by composite (categoryId_slug via category lookup). Paginate items with take+1 pattern. If viewerId, call getItemStatuses for the page of items.

    4. `getItemDetail(itemId, viewerId?)`: findUnique with include series.category. Count ownedBy. If viewerId, check OwnedItem and WishlistItem existence.

    5. `searchItems(q, opts)`: Use `name: { contains: q, mode: 'insensitive' }` with optional seriesId/categoryId (via series.categoryId) filter. Cursor pagination.

    6. `toggleOwned(userId, itemId)`: Wrap in `$transaction`. Check if already owned. If yes, delete and return `{ success: true, isOwned: false }`. If no, deleteMany wishlist first, then create owned (P2002 catch for idempotency). Return `{ success: true, isOwned: true }`.

    7. `toggleWishlist(userId, itemId)`: Same pattern as toggleOwned but reversed.

    8. `followCategory(userId, categoryId)`: Check existence, create or delete (P2002/P2025 pattern from social follow).

    9. `followSeries(userId, seriesId)`: Same pattern.

    10. `getItemStatuses(userId, itemIds)`: Two findMany with IN clause, return { ownedSet, wishlistSet } -- exact pattern from SocialService batch follow-status.

    11. `getUserOwnedItems(username, viewerId?, cursor?)`: Find user by username, paginate OwnedItem with item include (series, category). Group by category for response.

    **CollectionController (backend/src/collection/collection.controller.ts):**
    Route prefix: `@Controller('collection')`. Endpoints:

    - `GET /collection/categories` -- OptionalJwtAuthGuard -- getCategories()
    - `GET /collection/categories/:slug/series` -- OptionalJwtAuthGuard -- getSeriesByCategory(slug, viewerId)
    - `GET /collection/series/:categorySlug/:seriesSlug/items` -- OptionalJwtAuthGuard -- getItemsBySeries
    - `GET /collection/items/search` -- OptionalJwtAuthGuard -- searchItems (query params from searchItemsSchema)
    - `GET /collection/items/:id` -- OptionalJwtAuthGuard -- getItemDetail(id, viewerId)
    - `POST /collection/items/:id/owned` -- JwtAuthGuard -- toggleOwned(userId, itemId)
    - `POST /collection/items/:id/wishlist` -- JwtAuthGuard -- toggleWishlist(userId, itemId)
    - `POST /collection/categories/:id/follow` -- JwtAuthGuard -- followCategory
    - `POST /collection/series/:id/follow` -- JwtAuthGuard -- followSeries
    - `GET /collection/users/:username/owned` -- OptionalJwtAuthGuard -- getUserOwnedItems

    Use OptionalJwtAuthGuard (from Phase 3.1) on all read endpoints. Use JwtAuthGuard on write endpoints.
    Extract viewerId with `(req.user as any)?.userId || null` pattern.
