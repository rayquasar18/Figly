**CRITICAL Docker consideration for D-08:**
NestJS uses `tsc` (NOT webpack) for `nest build`. The compiled backend output in `backend/dist/` contains `require("@figly/shared")` calls. At runtime, Node.js resolves these via the `main` field in package.json.

If `main: ./src/index.ts` — Node.js cannot require `.ts` files natively. However, the Dockerfile builder stage runs `pnpm --filter @figly/shared build` which creates `dist/`. The key question: does the NestJS compiled output bundle shared code inline, or keep external requires?

Answer: NestJS uses `tsc` (confirmed in nest-cli.json — no webpack config), so compiled output keeps `require("@figly/shared")` as external. At runtime, Node resolves this to `main` field.

**Resolution per D-08:** Change `main` to `./src/index.ts` BUT the executor MUST verify Docker build works. If Docker fails, fall back to keeping `main: ./dist/index.js` and note the safety concern.

The most likely outcome: Docker will FAIL because `node dist/main.js` resolves `require("@figly/shared")` at runtime using `main: ./src/index.ts` which Node.js cannot load. In that case, keep `main: ./dist/index.js` and document the reason.
