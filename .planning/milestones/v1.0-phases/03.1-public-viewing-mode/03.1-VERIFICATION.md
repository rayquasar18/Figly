## Gap Detail

### PUB-01 Partial — postCount Hardcoded

The profile service (`backend/src/profiles/profiles.service.ts`) returns `postCount: 0` for every profile. The `_count` selector in `getProfile()` only includes `followers` and `following`, not `posts`. The comment says "Placeholder until Phase 3" but Phase 3 content work is complete.

**Impact:** Profile pages show 0 posts in the profile header count, even when the user has posts. The post grid itself (`ProfilePostGrid`) queries posts independently via `GET /posts/user/:username` and renders correctly — so posts are visible. The counter in `ProfileHeader` shows the wrong number (0).

**Fix required:**

In `backend/src/profiles/profiles.service.ts`, update the `_count` select to include posts:

```typescript
_count: {
  select: {
    followers: true,
    following: true,
    posts: true,  // ADD THIS
  },
},
```

And update the return value:
```typescript
postCount: user._count.posts,  // was: 0
```

This is a pre-existing issue from Phase 2 that was carried into Phase 3.1 without being corrected. It does not break public access, but it surfaces incorrect data on the profile that is visible to unauthenticated users.
