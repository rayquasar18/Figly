Create OptionalJwtAuthGuard and refactor all read-only backend endpoints to allow unauthenticated access. Add a public discovery feed endpoint.

Purpose: Enable non-authenticated users to view profiles, posts, comments, and a public feed in read-only mode, while keeping all write endpoints strictly authenticated.
Output: Backend API that serves content to both authenticated and unauthenticated users, with enriched interaction data (isLiked, isBookmarked, isFollowing) when authenticated.
</objective>

1. **Create OptionalJwtAuthGuard** at `backend/src/auth/guards/optional-jwt-auth.guard.ts`:
   - Extend `AuthGuard('jwt')` from @nestjs/passport
   - Override `handleRequest(err, user)` to return `user || null` instead of throwing on auth failure
   - This is the standard NestJS optional auth pattern

2. **Refactor PostsController** (`backend/src/posts/posts.controller.ts`):
   - REMOVE the controller-level `@UseGuards(JwtAuthGuard)` decorator
   - Apply `@UseGuards(OptionalJwtAuthGuard)` to read endpoints: `getUserPosts` (GET user/:username), `getPost` (GET :id)
   - Apply `@UseGuards(JwtAuthGuard, EmailVerifiedGuard)` to ALL write endpoints: `createPost`, `updateCaption`, `deletePost`, `likePost`, `unlikePost`, `bookmarkPost`, `unbookmarkPost`
   - Apply `@UseGuards(JwtAuthGuard, EmailVerifiedGuard)` to `getSavedPosts` (inherently personal)
   - For OptionalJwtAuthGuard endpoints, extract viewerId safely: `const viewerId = (req.user as any)?.userId || null;`

3. **Refactor PostsService** (`backend/src/posts/posts.service.ts`):
   - Change `getPost(postId: string, viewerId: string)` to `getPost(postId: string, viewerId: string | null)`
   - Change `getUserPosts(username: string, viewerId: string, ...)` to `getUserPosts(username: string, viewerId: string | null, ...)`
   - In both methods, wrap the like/bookmark batch queries in `if (viewerId)` check. When viewerId is null, use empty Sets so isLiked=false, isBookmarked=false
   - Do NOT change createPost, updateCaption, deletePost, toggleLike, toggleBookmark, getSavedPosts -- these always have a real userId

4. **Refactor ProfilesController** (`backend/src/profiles/profiles.controller.ts`):
   - `GET :username` (getProfile): change from `@UseGuards(JwtAuthGuard)` to `@UseGuards(OptionalJwtAuthGuard)`, extract viewerId with null-safe pattern
   - `PATCH me`, `GET search`: keep `@UseGuards(JwtAuthGuard)` / `@UseGuards(JwtAuthGuard, EmailVerifiedGuard)`
   - `GET check/:username`: no guard (already public)

5. **Refactor ProfilesService** (`backend/src/profiles/profiles.service.ts`):
   - Change `getProfile(username: string, viewerId: string)` to `getProfile(username: string, viewerId: string | null)`
   - Wrap the follow relationship queries (isFollowing, isFollowedBy) in `if (viewerId)` check. When null: isFollowing=false, isFollowedBy=false, isOwnProfile=false

6. **Refactor CommentsController** (`backend/src/comments/comments.controller.ts`):
   - REMOVE controller-level `@UseGuards(JwtAuthGuard, EmailVerifiedGuard)`
   - `GET posts/:postId/comments` (getComments): apply `@UseGuards(OptionalJwtAuthGuard)` -- comments are read-only data, no viewerId needed
   - `POST posts/:postId/comments` (createComment): apply `@UseGuards(JwtAuthGuard, EmailVerifiedGuard)`
   - `DELETE comments/:id` (deleteComment): apply `@UseGuards(JwtAuthGuard, EmailVerifiedGuard)`

7. **Refactor SocialController** (`backend/src/social/social.controller.ts`):
   - REMOVE controller-level `@UseGuards(JwtAuthGuard)`
   - `POST follow/:userId`, `DELETE follow/:userId`, `DELETE followers/:userId`: apply `@UseGuards(JwtAuthGuard, EmailVerifiedGuard)`
   - `GET :username/followers`, `GET :username/following`: apply `@UseGuards(OptionalJwtAuthGuard)`, extract viewerId with null-safe pattern
   - The SocialService.getFollowers/getFollowing methods already receive viewerId -- update them to accept `string | null` and wrap batch follow-status check in `if (viewerId)` (when null, no isFollowing flags needed, all return false)
