<task type="auto">
  <name>Task 1: Prisma schema extension with Post, interaction, and hashtag models</name>
  <files>backend/prisma/schema.prisma</files>
  <action>
Add the following models to the existing Prisma schema. Follow the exact schema from 03-RESEARCH.md Pattern 1:

1. **Post model**: id (cuid), userId (FK to User), caption (VarChar 2200, nullable), createdAt, updatedAt. Relations: user, media (PostMedia[]), likes (Like[]), comments (Comment[]), bookmarks (Bookmark[]), hashtags (PostHashtag[]). Indexes on userId and createdAt. Map to "posts".

2. **PostMedia model**: id (cuid), postId (FK to Post, onDelete Cascade), mediaId (FK to Media, onDelete Cascade), position (Int, 0-indexed for carousel ordering). Unique constraint on [postId, position]. Index on postId. Map to "post_media".

3. **Like model**: id (cuid), userId (FK to User, onDelete Cascade), postId (FK to Post, onDelete Cascade), createdAt. Unique constraint on [userId, postId]. Index on postId. Map to "likes".

4. **Comment model**: id (cuid), userId (FK to User, onDelete Cascade), postId (FK to Post, onDelete Cascade), parentId (String?, self-reference for 1-level-deep threading, onDelete Cascade), content (VarChar 1000), createdAt. Self-relation "CommentReplies" via parentId. Indexes on [postId, createdAt] and [parentId]. Map to "comments".

5. **Bookmark model**: id (cuid), userId (FK to User, onDelete Cascade), postId (FK to Post, onDelete Cascade), createdAt. Unique constraint on [userId, postId]. Index on [userId, createdAt]. Map to "bookmarks".

6. **Hashtag model**: id (cuid), name (String, unique, lowercase without #), posts (PostHashtag[]). Map to "hashtags".

7. **PostHashtag model**: id (cuid), postId (FK to Post, onDelete Cascade), hashtagId (FK to Hashtag, onDelete Cascade). Unique constraint on [postId, hashtagId]. Index on hashtagId. Map to "post_hashtags".

8. **User model additions**: Add posts (Post[]), likes (Like[]), comments (Comment[]), bookmarks (Bookmark[]) relations.

9. **Media model addition**: Add postMedia (PostMedia[]) relation.

After updating the schema, run `cd backend && npx prisma generate` to regenerate the Prisma client. Do NOT run `prisma db push` (that requires Docker).

Verify the schema is valid with `cd backend && npx prisma validate`.
