## Remaining Issues

### BACK-05: Swagger Setup Missing (Unsatisfied)

**Severity:** Medium
**Root Cause:** The original audit (2026-03-26) incorrectly marked BACK-05 as "satisfied" claiming "Swagger wiring in main.ts survived merge." In reality, the Phase 13 main.ts contained `DocumentBuilder`, `SwaggerModule.setup('api/docs', ...)`, and `cleanupOpenApiDoc` -- all lost in the Phase 15-01 regression. Phase 17 was scoped to restore only the gaps identified in the original audit, which did not include BACK-05.

**Evidence:**

- `@nestjs/swagger: 11.2.6` is installed in backend/package.json
- backend/src/main.ts has NO import of DocumentBuilder, SwaggerModule, or cleanupOpenApiDoc
- `grep -rn "swagger\|SwaggerModule\|DocumentBuilder" backend/src/` returns zero matches (only package.json)
- The correct code existed in commit `b8f512c` (Phase 13-04)

**Fix Required:** Restore Swagger setup in main.ts (approximately 10 lines from commit b8f512c).

### BACK-03: app.useLogger Not Restored (Tech Debt)

**Severity:** Low
**Evidence:** Phase 13's main.ts had `NestFactory.create(AppModule, { bufferLogs: true })` and `app.useLogger(app.get(Logger))` to route all NestJS internal logs through Pino. Current main.ts uses default `NestFactory.create(AppModule)` with `console.log` for the startup message. LoggerModule IS wired in app.module.ts so HTTP request logging works via Pino, but NestJS bootstrap and internal framework logs bypass Pino.

**Impact:** Functional -- HTTP request logging works. Log aggregation tools will see request logs in structured JSON but framework startup logs in plain text.
